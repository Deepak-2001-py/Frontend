E · How the three roles connect to the grading pipeline
Admin
creates every account (USERS + Cognito group) · assigns teachers to CLASSES · enrolls students (MEMBER rows) · approves resets · reads AUDIT_LOG · never touches grades
→
Teacher
owns CLASS#… · creates ASSIGNMENTS (classId FK → Table 1, 1a) · uploads QPs + rubrics · reviews rubric · works SQS review queue · overrides + publishes grades
→
Student
member of classes (GSI1 "my classes") · sees ASSIGNMENTS of enrolled classes only · uploads answers → SUBMISSIONS keyed by their userId · fixes OCR · gets SNS notify on publish
Authorization chain on every pipeline call: JWT role claim (route access) → classIds claim / CLASSES membership check (row access) → PK ownership check (SUBMISSION#<own userId> only). All three checks live in the λ handlers of 2a.

(+ hygiene)

◆ FAN-IN GATE (λ readiness check, fired from DynamoDB Streams on both tables)
Grading fires only when QP status = rubric_reviewed AND SUBMISSION status = corrected. Whichever side finishes second wins the race and triggers grading — enforced by a conditional write on status, so it can never fire twice.
Case: rubric not yet teacher-reviewed at due time → grade anyway with gradingMode: "ai_reference_unreviewed" and auto-flag for review.
